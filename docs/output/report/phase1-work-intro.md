## 二、作品正文（≤800 字）

边缘设备跑低比特大模型，常规做法是先反量化再做高精度乘加。访存和转换的开销常常吃掉低比特带来的收益，首字延迟（TTFT）和能耗都偏高；后台任务一多，系统体验更是塌方。赛题要求在现有 OS 架构里把系统 AI 任务的效率做上去，纯应用层 Demo 撑不起「系统级创新」这块招牌。

我们的作品叫「LUT-SA」。引擎用的是开源 T-MAC（EuroSys 2025）的比特级查找表范式：把低比特混合精度矩阵乘换成查表 + 加法，反量化乘加直接消失。算法内核经 NDK 封装后，以 OpenHarmony / HarmonyOS 的 SystemAbility 注册为系统级加速服务，对外提供模型加载、推理、指标回传三个能力。调度侧感知通知、前台状态与负载，动态调优先级与预取，构成「感知 → 调度 → 加速」闭环，整条链路都在用户态跑，不动内核。

技术路径三层：

- **计算层**：适配 T-MAC LUT Kernel，重点处理 ARM 端的访存与 LUT 表布局。
- **服务层**：按 SAMgr 注册 LUT SA，对外暴露统一加速接口，应用按需取 proxy。
- **策略层**：感知信号 → 优先级 / 预取 / 节流策略，可演示。

公开评测里，T-MAC 相对 llama.cpp 在多种边缘 CPU 上吞吐更优（本仓 `docs/profiling_data.md`：BitNet-3B 在 M2-Ultra 单核约 22.08 对 6.49 tokens/s；树莓派 5 单核约 8.03 对 1.37 tokens/s）。我们以此为基线，计划在鸿蒙 / 模拟器或 ARM 设备复现后补实测数据。复赛可以再叠官方 NPU / CANN 量化路径做对照，强化「异构调度」的故事。

作品的价值是把一个计算范式产品化成系统服务：端侧部署门槛降下来，隐私本地推理与低功耗生成就有了底座。
